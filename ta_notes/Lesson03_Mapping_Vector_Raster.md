### 2. Two ways to store space: vector vs raster (8 min)

| | **Vector** | **Raster** |
|---|---|---|
| Idea | Shapes with coordinates + a table of attributes | A grid of cells, each holding one number |
| Types | Points, lines, polygons | Just cells (pixels), but can have many bands |
| Ag examples | Soil-sample sites, field boundaries, roads, county lines | Elevation (DEM), satellite NDVI, rainfall surface, yield-monitor map |
| Good for | Discrete things with precise edges + attributes | Continuous things that vary everywhere |
| Python library | `geopandas` (built on `shapely` + `pandas`) | `rasterio` (+ `numpy`) |
| File formats | Shapefile (.shp), GeoPackage (.gpkg), GeoJSON | GeoTIFF (.tif) |

Analogy that sticks: **vector = a drawing, raster = a photo.** Zoom into a drawing and lines stay crisp; zoom into a photo and you see pixels.

Connect to Lesson 1: a raster *is* the 2D NumPy array from the "your first raster" bonus cell; a vector layer *is* a pandas DataFrame with one extra column called `geometry`.

### 3. Vector I — points from a plain table (12 min)

```python
samples = pd.DataFrame({
    "site":        ["S1", "S2", "S3", "S4", "S5", "S6", "S7", "S8"],
    "lon":         [-88.237, -88.231, -88.225, -88.236, -88.229, -88.223, -88.234, -88.226],
    "lat":         [ 40.093,  40.094,  40.092,  40.099,  40.100,  40.098,  40.103,  40.103],
    "yield_bu_ac": [178, 185, 172, 190, 196, 181, 188, 175],
})

# Turn the table into a GeoDataFrame: same table + a geometry column + a CRS
pts = gpd.GeoDataFrame(
    samples,
    geometry=gpd.points_from_xy(samples.lon, samples.lat),
    crs="EPSG:4326",          # lon/lat in degrees — what GPS gives you
)
pts.head()
```

Point out on screen: it *looks like* a DataFrame — because it is one — with a `geometry` column of `POINT (...)` objects. Then:

```python
print(pts.crs)          # EPSG:4326 (WGS 84)
print(type(pts))        # GeoDataFrame
pts.geometry.x          # the lon of each point, pulled back out
```

First map — one line, then labels:

```python
ax = pts.plot(column="yield_bu_ac", cmap="YlGn", legend=True,
              markersize=120, edgecolor="black", figsize=(6, 6))

for x, y, label in zip(pts.geometry.x, pts.geometry.y, pts.site):
    ax.annotate(label, (x, y), xytext=(5, 5), textcoords="offset points")

ax.set_title("Corn yield at soil-sample sites")
ax.set_xlabel("Longitude"); ax.set_ylabel("Latitude")

```

Talking points:
- `.plot(column=...)` colors by an attribute — the map version of a colorbar. Same rule as Lesson 1: **title, axis labels, legend**.
- The `for` loop with `zip()` is exactly the Lesson 1 loop pattern — nothing new, just applied to a map.
- Ask: *"Where are the high yields?"* — students should notice they cluster in the north-center. Hold that thought for the activity.

### 4. Vector II — a polygon and the CRS question (10 min)

```python
# A field boundary: list of (lon, lat) corners, closed automatically
corners = [(-88.240, 40.090), (-88.220, 40.090), (-88.220, 40.105), (-88.240, 40.105)]

field = gpd.GeoDataFrame({"name": ["North field"]},
                         geometry=[Polygon(corners)], crs="EPSG:4326")

fig, ax = plt.subplots(figsize=(6, 6))
field.plot(ax=ax, facecolor="none", edgecolor="black", linewidth=2)
pts.plot(ax=ax, column="yield_bu_ac", cmap="YlGn", legend=True,
         markersize=120, edgecolor="black")
ax.set_title("North field with sample sites")
plt.show()
```

Note the pattern: create `fig, ax`, then call each layer's `.plot(ax=ax, ...)`. **Layers stack in the order you draw them.**

Now the trap — ask *"How big is this field?"* and run:

```python
field.area          # ~0.0003 ... and a warning. 0.0003 WHAT?
```

- Degrees aren't a unit of area. One degree of longitude is ~85 km in Illinois but ~0 km at the pole.
- **A CRS (coordinate reference system) says what the numbers mean.** EPSG:4326 = degrees on the globe. For measuring, we need a *projected* CRS in meters — for Illinois, UTM zone 16N = **EPSG:32616**.

```python
field_utm = field.to_crs("EPSG:32616")
print(field_utm.geometry.iloc[0].bounds)          # now in meters
area_acres = field_utm.area.iloc[0] / 4046.86
print(f"Field area: {area_acres:.0f} acres")      # ~700 acres

pts_utm = pts.to_crs("EPSG:32616")
d = pts_utm.geometry.iloc[0].distance(pts_utm.geometry.iloc[1])
print(f"S1 to S2: {d:.0f} m")                     # ~520 m
```

Rules of thumb (put on a slide):
- **Always check `.crs` first.** Two layers must share a CRS before you overlay or measure them.
- **Degrees for storing and displaying; meters for measuring.** `.to_crs()` converts.
- No CRS (`None`)? geopandas can't convert it — you must tell it what the numbers are with `.set_crs()`.

### 6. Raster — build it, map it, save it, read it back (15 min)

Start from the Lesson 1 bonus cell, but now give the grid **real coordinates**:

```python
np.random.seed(444)
west, east, south, north = -88.245, -88.215, 40.085, 40.110    # covers the field
ncols, nrows = 60, 50

lon = np.linspace(west, east, ncols)
lat = np.linspace(north, south, nrows)      # north first: rasters store the TOP row first, like an image
LON, LAT = np.meshgrid(lon, lat)

# A gently tilted "elevation" surface: higher in the north-west, plus noise
elev = (225
        - 12 * (LON - west) / (east - west)
        +  6 * (LAT - south) / (north - south)
        + np.random.normal(0, 0.8, size=(nrows, ncols))).astype("float32")

print(elev.shape, elev.min().round(1), elev.max().round(1))

plt.imshow(elev, cmap="terrain", extent=[west, east, south, north])
plt.colorbar(label="Elevation (m)")
plt.title("Simulated elevation (m)")
plt.xlabel("Longitude"); plt.ylabel("Latitude")
plt.show()
```

- `extent=` is what turns "an image" into "a map": it tells matplotlib which coordinates the corners are.
- `elev[0, 0]` is the **north-west** cell; `elev[-1, -1]` is south-east. Row index goes down = south.

Save as a GeoTIFF — an image file that carries its own CRS and position:

```python
xres = (east - west) / ncols
yres = (north - south) / nrows
transform = from_origin(west, north, xres, yres)   # top-left corner + cell size

with rasterio.open("elevation.tif", "w", driver="GTiff",
                   height=nrows, width=ncols, count=1, dtype="float32",
                   crs="EPSG:4326", transform=transform) as dst:
    dst.write(elev, 1)
```

Read it back exactly the way you'd read a real DEM or satellite image, and overlay the vector layers:

```python
with rasterio.open("elevation.tif") as src:
    print(src.crs, src.shape, src.res)
    print(src.bounds)

    fig, ax = plt.subplots(figsize=(7, 6))
    show(src, ax=ax, cmap="terrain")                              # raster layer
    field.plot(ax=ax, facecolor="none", edgecolor="white", linewidth=2)   # polygon
    pts.plot(ax=ax, column="yield_bu_ac", cmap="YlGn",             # points
             edgecolor="black", markersize=120, legend=True)
    ax.set_title("Yield samples over elevation")
    plt.show()
```

Talking points:
- **Three layers, one map** — raster underneath, polygon, then points. Works because all three share EPSG:4326.
- The `with rasterio.open(...) as src:` block is like opening a book: read what you need inside the block; it closes itself afterwards.
- `src.read(1)` gives you the plain NumPy array back — everything from Lesson 1 (`.mean()`, comparisons, slicing) works on it.

**Check for understanding:** Change `cmap="terrain"` to `"viridis"` and the polygon edge to red. Then print `src.read(1).mean()`.

### 7. Bridge — pull raster values out at the points (5 min)

*"Does yield depend on elevation?"* To ask that, each sample point needs the elevation under it:

```python
coords = list(zip(pts.geometry.x, pts.geometry.y))      # [(lon, lat), ...]

with rasterio.open("elevation.tif") as src:
    pts["elev_m"] = [value[0] for value in src.sample(coords)]

pts[["site", "yield_bu_ac", "elev_m"]]
```

Now it's a two-column table again — and Week 2 takes over:

```python
from scipy import stats

fit = stats.linregress(pts.elev_m, pts.yield_bu_ac)
print(f"slope = {fit.slope:.2f} bu/ac per m,  R² = {fit.rvalue**2:.2f},  p = {fit.pvalue:.2f}")

plt.scatter(pts.elev_m, pts.yield_bu_ac)
plt.plot(pts.elev_m, fit.intercept + fit.slope * pts.elev_m, "--")
plt.xlabel("Elevation (m)"); plt.ylabel("Yield (bu/ac)")
plt.title("Yield vs elevation at 8 sample sites")
plt.show()
```

(With the seed above: slope ≈ 2.0, R² ≈ 0.28, p ≈ 0.17 — weak, as it should be with 8 points.) **Leave this on screen; it's the input to the activity.**

**Pair — 3 min:** Compare answers with a neighbor. Together, finish this sentence with a number and a word:
> "Two sample sites ___ m apart probably have ___ (more / less) similar yields than two sites 1 km apart, so the regression errors are probably ___ (independent / not independent)."

**Share — 5 min:** Call on 2–3 pairs. Then reveal the residual map:

```python
pts["resid"] = pts.yield_bu_ac - (fit.intercept + fit.slope * pts.elev_m)

fig, ax = plt.subplots(figsize=(6, 6))
field.plot(ax=ax, facecolor="none", edgecolor="black")
pts.plot(ax=ax, column="resid", cmap="RdBu", vmin=-12, vmax=12,
         legend=True, markersize=160, edgecolor="black")
for x, y, r in zip(pts.geometry.x, pts.geometry.y, pts.resid):
    ax.annotate(f"{r:+.0f}", (x, y), xytext=(6, 6), textcoords="offset points")
ax.set_title("Regression residuals (blue = yield higher than elevation predicts)")
plt.show()
```

**Landing the point (TA script):**
- The residuals are not scattered at random — the blues sit together in the north-center, the reds at the edges. Nearby sites share what the model missed (drainage? soil type? a wet spot?).
- That's a violation of *independence of errors*, assumption #2 in Module 02. Ordinary regression doesn't know the sites have locations. **Every method from Module 03 onward — variograms, kriging, spatial autocorrelation — is a way of putting the map back into the statistics.**
- On Q1: a `dict` per site (`{"site": "S1", "lon": ..., "lat": ..., "yield": ...}`) is the natural answer; a GeoDataFrame is a table of those *plus* a CRS and geometry methods (`.to_crs`, `.area`, `.distance`, `.plot`). Same data, more power.

Seed question on the board: *"If two neighboring sites both have high residuals, is that a coincidence?"* You write every question on the board; end by circling the 2–3 that Module 03/04 will answer.

## Anticipated Questions & Pitfalls (TA cheat sheet)

| Situation | Response |
|---|---|
| `ModuleNotFoundError: rasterio` | Run the setup cell (`!pip install -q rasterio`). In Colab, re-run it after every runtime restart. |
| `field.area` gives 0.0003 + a warning | It's in degrees². Convert with `.to_crs("EPSG:32616")` first. This is the lesson, not a bug. |
| `.to_crs()` errors with "Cannot transform naive geometries" | The layer has no CRS. Use `.set_crs("EPSG:4326")` to *declare* it (only if you know that's what the numbers are), then `.to_crs()`. |
| Raster appears upside-down | `imshow` assumes row 0 is the top. Build the array north-first (as we did) or pass `origin="lower"` — not both. |
| Points don't show up on the raster | CRS mismatch, or the points are outside the raster's extent. Print `pts.crs`, `src.crs`, `src.bounds`. |
| `plot(column=...)` throws for text columns | Add `categorical=True` for strings; numeric columns get a colorbar automatically. |
| "Which EPSG do I use?" | Degrees: 4326. Illinois in meters: 32616 (UTM 16N). Elsewhere: look up the UTM zone on epsg.io. |
| Map of `states` shows a tiny US and huge empty ocean | Alaska/Hawaii stretch the extent. Use `ax.set_xlim/ylim`. |
| Student asks "why not just use Google Maps / ArcGIS?" | Same ideas, but here every step is code you can rerun on 500 fields. |
